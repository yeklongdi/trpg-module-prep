# 目录、总索引与具名引用规范

## 模组目录

```text
模组名/
├─ 带团文档/
│  └─ 第01章 章节名/
│     ├─ 模组名 第01章 章节名 流程（文字）.md
│     ├─ 模组名 第01章 章节名 流程（白板）.canvas
│     └─ 模组名 第01章 章节名 主持CG.md
├─ 怪物/
│  ├─ 模组名 怪物数据.md
│  └─ 模组名 怪物描述.md
├─ 模组/
├─ 资料附件/
├─ npc/
│  ├─ 模组名 NPC人设.md
│  ├─ 模组名 NPC数据.md
│  └─ 模组名 NPC任务与地点.md
└─ 模组总索引.md
```

执行时替换模组、章名及编号。没有章节划分时建立一章，章名依据原文内容。原始正文及附录归【模组】，保留原件并按需引用或复制；地图、立绘、手册及备份归【资料附件】，复用已有有效资源，不重复复制。

每章只生成三类资料；玩家事件清单、任务、线索、遭遇和分支并入文字流程相应S小节，并在白板和CG定位同一条目。不另建备团入口、读取清单、问题报告、完成记录、立绘说明或单个实体文件。跨章节入口在总索引链接各章。

## 总索引内容

H1写【模组名 · 模组总索引】。以下内容作为H2章节：

| 章节 | 内容 |
| --- | --- |
| 备团入口 | 章节、NPC、怪物、地图与常用查阅链接 |
| 规则与模组概况 | 规则版本、模组版本、译本、范围与准备状态 |
| 章节及实体索引 | S场景、L地点、N角色、M怪物、C线索，编号、名称、来源、状态与主条目 |
| 资料读取清单 | 路径、用途、版本、实际读取状态、重复与冲突 |
| 待确认事项 | Q编号、问题摘要、来源、影响、阻塞／可选、处理、恢复点；无问题写暂无 |
| 完成情况与修改记录 | 完成范围、未完成部分、读取覆盖、问题解决及生成／修改／删除文件 |

在【章节及实体索引】下分【场景索引】【NPC索引】【怪物索引】小节，以同一行记录对象名称、主条目和可定位原文来源。没有对应实体时写【原文无NPC】或【原文无怪物】；资料没读完时写未确认并登记问题，不能把未知当作没有。

NPC索引增加【已确认形态】列，便于人设、状态、立绘和检查脚本对照。多形态用中文分号【；】隔开；只有一个外观形态也写该形态的实际称呼，如【常态】。不要额外猜出原形、伪装或诅咒。

下面只是格式示例，执行时用原文对象及实际路径、来源替换：

```markdown
### NPC索引

| 编号 | 名称 | 已确认形态 | 主条目 | 来源 |
| --- | --- | --- | --- | --- |
| N001 | 酒馆老板 | 常态 | [[npc/模组名 NPC人设#N001 酒馆老板|N001 酒馆老板 · 人设]] | 原文文件、章节或页码 |
```

S条目记录场景触发、DC、奖励、遭遇数量、部署及条件，链接NPC／怪物完整数据。不要在所有文档各自维护整套统计数据；使用处明确定位数据文档。L、C条目带名称，Q条目带问题摘要。

## 标题与命名

- 文件名包含模组名及类别或章名；H1写模组及文档类别。
- H2以【编号 实际名称】组织实体，例如【S001 酒馆委托】【N001 酒馆老板】【M001 食尸鬼】。
- H3以【编号 实际名称 · 用途】组织描写、能力与场景条件。NPC外貌H3还包含形态名。
- 不能只有S001、N001或M001，也不能把名字仅写在正文、表格或链接别名里。无名角色用原文身份加地点消歧，不编姓名；同名不同数据须明确变体或版本。
- H2使用玩家可辨认的姓名或称呼；隐藏身份放主持人秘密。H3形态名称供主持人选择对应段落，标题本身不作为朗读内容。
- 编号稳定，不因文档排序重新编号；更名同步索引、标题、引用目标、链接显示名称与图片名称。

## 引用格式

使用模组根目录内的相对路径和真实标题锚点。推荐Obsidian内部链接；Markdown链接也可，但目标路径和标题必须能实际定位。

```markdown
[[npc/模组名 NPC数据#N001 酒馆老板|N001 酒馆老板 · 数据]]
[[npc/模组名 NPC任务与地点#N001 酒馆老板|N001 酒馆老板 · 任务与地点]]
```

每个S、N、M条目能双向定位同类相关资料；链接显示名称和用途。白板同S节点正文包含文字与CG对应锚点；Markdown中的白板导航可链接Canvas文件，注明S编号和名称。

原始参考文件可以只读引用；可用链接优先复用。生成资料之间使用可迁移的内部路径；引用外部资料时记来源与访问条件。外部链接、规则版本和源文件真实性需实际核验，结构脚本不能代替这一步。
