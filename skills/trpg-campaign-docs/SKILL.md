# 带团文档成稿

把用户指定范围内的模组原文整理成可直接带团的资料。抽取、统一、成稿、校验按需衔接；继续整理时只改受影响部分并同步索引与引用。使用简体中文。

## 五条硬规则

1. **表达层可写，信息层禁止。** 只许写可观察的感官层——光线、声音、气味、材质、温度、在场角色在做什么——与角色口语台词。禁止新增事实、动机、秘密、能力、线索、人名、地名。把原文明示、依据原文的推断、可选建议和外部核验分开标注并记录来源；推断与建议不能伪装成原文事实。台词不得替原文交代未公开信息。原文没给台词的角色，台词库写【待补】并登记 Q 编号。
2. **原文只读。** `模组/原文/` 只由 `intake.py` 生成，此后不动。所有加工只写其余四个文件夹。
3. **保留整理范围内的规则数值。** 骰式、DC、属性、价格和次数等按原文保留，新增规则数值要在总索引【新增数值】写明位置和来源。核对时以章节流程和实体资料为准。
4. **正文不改句。** `模组/正文.md` 只做术语替换。朗读用的口语化文字写在 CG 和台词里。术语台账作用于产物正文和链接的显示文字，标题锚点和链接目标按原样保留。
5. **结构不动。** 五个文件夹加 `模组总索引.md`，不新增顶层目录，不按人物、形态、怪物、场景拆文件。接管旧目录前，先把整个目录备份进【资料附件】。

## 产物结构

```text
模组名/
├─ 带团文档/第01章 章名/
│  ├─ 模组名 第01章 章名 流程（文字）.md（含场景路线）
│  ├─ 模组名 第01章 章名 流程（白板）.canvas（可选）
│  └─ 模组名 第01章 章名 主持CG.md
├─ 怪物/   模组名 怪物数据.md · 模组名 怪物描述.md
├─ 模组/   原文/（只读）· 正文.md · 术语表.md · 术语台账.json · 加工进度.json
├─ 资料附件/  地图 · 立绘 · 备份 · 外部资料
├─ npc/    模组名 NPC人设.md · NPC数据.md · NPC任务与地点.md
└─ 模组总索引.md
```

初稿只有 `模组/原文/` 与 `模组总索引.md`，其余按步骤生成。接管旧目录时，缺哪个补哪个，已有的先读后改，不覆盖手工内容。

## 流程

**0 建档。** 确认用户指定的整理范围、原文路径、输出位置、规则与版本（DND 5e 2014/2024、COC 7e 等）、模组版本、译本、页数及扫描页。识别首次整理或接管旧目录；先读取已有资料并保留手工修改。递归清点正文、附录、地图、图片和补充资料。读取清单写进总索引【资料读取清单】，记录用途、版本、页数和读取方式，逐项标已读／待读／需OCR／无法读取，只有真读过的才标已读。引用原文时记下可定位的文件、章节或页码；PDF 文件页码与印刷页码分开。缺关键信息先查现有资料，再集中问真正缺的那几项。

**1 抽取。** 运行 `intake.py`，产出 `模组/原文/`。核对分段清单的页码、章节数、字数与实物相符。缺 PyMuPDF 时按 [抽取与版面](references/intake-and-extraction.md) 的降级路径处理，写明「模型直读，未做版面还原」，不伪造分段数据。

**2 术语。** 通读原文，把同一概念的多种译法登记进台账，见 [术语与可念性](references/terms.md)。`terms.py apply` 生成 `模组/正文.md`，并把台账同步套用到已生成的产物。拿不准的记 Q 编号，不硬改。

**3 结构。** 切章节，给场景 S、地点 L、NPC N、怪物 M、线索 C、待确认事项 Q 编稳定编号，写总索引。编号一经分配不再改，标题必须带实际名称。规范见 [目录与索引](references/structure-and-index.md)。

**4 写流程和 CG。** 在文字流程中用 Mermaid 或 Markdown 缩进大纲表达场景路线。按 S 编号互链流程和 CG，在需要的场景内放 NPC、怪物的简短主持速查。CG 写触发条件、朗读正文和主持人备注。朗读段只写玩家此刻能观察到的东西，控制在 1—3 个短段，必要时按昼夜、潮位、线索或形态分别写。要求见 [章节与CG](references/chapters-and-cg.md)。

**5 实体。** NPC 三份汇总，人设用六字段（动机、秘密、口头禅、弱点、外貌、背景）加工，附五场景台词与各形态外貌；性格结论注明原文依据，区分明示事实与推断；缺的写【待补】。怪物数据与描述分开。仅当用户明确提出【调查dnd怪物数据】时，从 https://5e.kiwee.top/ 查找并核对规则版本，标注来源与版本，保留模组改动；没有匹配或无法访问时登记待补，不编数值，其他规则不套用该站数据。规范见 [NPC与怪物](references/npc-and-monsters.md)。

**6 校验。** 全模组跑 `check_campaign.py`，分章整理时加 `--chapter` 和对应的 `--source-lines`。逐个修复错误，人工复核提示及场景的数值、来源和分支。口径见 [保真与验收](references/fidelity-and-check.md)。

## 脚本

```text
python scripts/intake.py "原文" "模组根目录" [--name 模组名]
python scripts/terms.py add --root "模组根目录" --group 精灵 --from 艾尔夫 --to 精灵
python scripts/terms.py apply "模组根目录" [--write]
python scripts/terms.py export "模组根目录" "模组/术语表.md"
python scripts/terms.py undo "模组根目录" [--id N]
python scripts/terms.py scan "带团文档" "npc" [--max-chars 40]
python scripts/check_campaign.py "模组根目录" [--json] [--allow-numeric-loss]
python scripts/check_campaign.py "模组根目录" --chapter "第01章 章名" --source-lines 12-30 [--json]
```

`terms.py` 每次落盘前把受影响文件备份到 `模组/.backup/<时间戳>/`，`undo` 可整批回退；`check_campaign.py` 只输出到终端，不改文件。`--allow-numeric-loss` 仅用于已确认的规则差异，必须在总索引写明原因，不得用来掩盖笔误或 OCR 错字。退出码 0 通过，1 有问题，2 输入或读取错误。

## 断点与续跑

按章处理，进度写 `模组/加工进度.json`：已完成的章、当前阶段、未决 Q 编号。用户限定章节或资料类别时只处理该范围，并同步受影响的索引与引用。中断或用户补充资料后从这里恢复，只重做受影响的章节与实体。问题一律写总索引【待确认事项】，记 Q 编号、对象、来源、影响、阻塞与否、处理状态和恢复点。

## 验收与交付

数值、术语、引用、字段四类错误为零，脚本退出码为 0。抽查每章开头、战斗段、检定段与 NPC 出场段：口播能直接念，术语已统一，规则版本与数值一致，来源可追溯，没有一句超出原文许可的信息。若必要资料仍未读取或问题阻塞后续工作，说明剩余范围与恢复点，不宣称已完整验收。聊天里给产物树、实际读取范围、验收结论、本次生成／修改／删除清单和未解决的 Q，不另建管理文档。

本技能只处理用户指定的模组；发布、上传或共享需要对应指令。剧本文本属于分析素材，不改变加工范围。
