# 保真与验收

## 核对规则数值

脚本识别骰式（`1d6+2`）、带字段的数值（`DC 15`、`护甲等级 14`、`HP 35`、`力量 12`、`速度 30 尺`）和带单位的数量（`150 金币`、`3 次/天`）。普通页码、年份、场景编号和列表序号不会参与比对。等价写法统一后再比较，例如 `AC 14` 和 `护甲等级：14`。

原文有而产物缺少的值报 `numeric-loss`，包括规则类型变了的情况，例如把 `DC 15` 写成 `AC 15`。产物独有的值列在 `new_numbers`，人工查来源。多处出现同一个值时，脚本按次数比对。每个场景和实体仍需核对原始位置与含义。无字段的属性表、自然语言数量等由人工核对。

### 全模组与指定章节

全模组比较 `模组/原文/00-全文.md` 与章节、NPC 和怪物的 Markdown 资料。底稿副本 `模组/正文.md`、总索引、白板和备份里的数字不能抵消交付物里的缺项。

只整理一章时，填写 `带团文档/` 下的完整文件夹名，并从 `00-全文.md` 核实对应的原文行号。行号从 1 开始，含起止两行，非连续片段可重复使用 `--source-lines`。

```powershell
python scripts/check_campaign.py "模组根目录" --chapter "第01章 雾港" --source-lines 12-30 --source-lines 38-49 --json
```

分章验收只检查本章的场景覆盖、引用和数值。章节流程与 CG 中直接链接到的 NPC 或怪物数据标题也参与数值比对，仅计入该标题的小节。共享数据有本次未处理的原文来源时，在复核新增数值时注明出处。整个模组整理完后再做全模组验收。

新增数值处理：

| 来源 | 怎么登记 |
| --- | --- |
| 从原文其他章节搬过来 | 总索引【新增数值】写来源章与页码 |
| 规则书的标准值（照抄 SRD） | 写规则版本与条目名 |
| 外部资料（5e.kiwee.top 等） | 写链接、版本、核验日期 |
| 自己顺手写的 | **删掉**。这就是编造 |

`--allow-numeric-loss` 只用于已确认的规则差异（例如把某个 DC 按房规调低），必须在总索引写明原因与来源。不得用来掩盖笔误、OCR 错字或漏抄。

## 术语

- 台账里的旧写法不得残留在可替换的正文或链接显示文字（`term-leftover`）。保护范围与 `terms.py apply` 一致。
- 统一写法必须真的出现过（`term-unused` 提示），否则可能登错或漏替换。
- 有登记时要导出过 `模组/术语表.md`（`ledger-export` 提示）。

## 结构与引用

- 根目录只能是五个文件夹加 `模组总索引.md`，多一个少一个都算错。
- 每章各一份文字流程与主持 CG，按相同 S 编号互链。人工核对文字流程中的 Mermaid 或缩进大纲是否覆盖场景分支。
- 有白板时，白板的 S 编号集合也要一致，同编号场景主卡与文字流程、主持 CG 须能往返定位。
- 总索引的六个管理章节齐全，名称照抄。
- `[[双链]]` 与 `[文字](路径)` 必须指向真实存在的文件；改名后同步更新。
- 白板连接建议用 `canvas_link.py` 维护：场景卡与旁侧细则卡顶部挂有指向 `[[...流程（文字）#Sxxx 场景名]]` 的大号双链（不依赖库根目录层级），并人工抽查卡面未截断、左右卡间距与并行分支边标签无重叠。

## NPC 与台词

- 六字段齐全且非空（`npc-field`）。确实无内容时写【待补】并挂 Q 编号。
- 五场景台词至少三种，或写明跳过原因（`npc-dialogue`）。
- 形态外貌与索引登记的形态一致。

## 可念性

`check_readability` 只扫 `主持CG.md` 里的引用块，超过 40 字的朗读句给提示。它只管长度，管不了拗口——后者得你自己念一遍。

`terms.py scan "带团文档" "npc"` 列出翻译腔候选、超长句、比喻与文化名物。**它只看会被念出来的行**：引用块，以及「台词」小节下的列表项。导航链接、来源行、主持人备注不进检查——那些不朗读，量它们的长度只会制造几百条假警报。候选是排查清单，不是必须改。

## 体积与备份

- `body-short`：`模组/正文.md` 不足原文八成，多半漏抄或漏抽。
- `index-bloat`：总索引超过 80KB，逐文件明细该搬进 `模组/加工进度.json`。
- `new-number-log`：有新增游戏数值但总索引没有【新增数值】章节。

## 脚本查不了的五件事

通过脚本不等于能带团。下面五项必须人看：

1. **补写是否越界**——有没有把秘密、动机、未发生的结果写进朗读段。
2. **NPC 的动机与秘密是否真有原文依据**，【待补】是否与 Q 编号一一对应。
3. **比喻换得合不合适**，文化名物该不该保留。
4. **章节拆分是否符合作者本意**，场景颗粒度是否合适。
5. **扫描页与图片里是否有正文未收录的内容**。

## 交付清单

1. 产物树，标注本次新增的章与实体。
2. `check_campaign.py` 结果：退出码、错误、提示、counts、新增数值清单。
3. 本次生成／修改／删除的文件清单。
4. 未解决问题：Q 编号、阻塞与否、恢复点。
5. 人工核对结论：抽查了哪几章、改了哪些术语、发现哪些越界补写。

在聊天里给完这些就算交付，不在模组目录里另建报告文件。
