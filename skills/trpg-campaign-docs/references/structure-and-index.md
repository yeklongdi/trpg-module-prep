# 目录与索引

结构和编号是这份资料的骨架。骨架一乱，后面写的口播再好也查不到。

## 产物树

```text
模组名/
├─ 带团文档/
│  └─ 第01章 章节名/
│     ├─ 模组名 第01章 章节名 流程（文字）.md（含场景路线）
│     ├─ 模组名 第01章 章节名 流程（白板）.canvas（可选）
│     └─ 模组名 第01章 章节名 主持CG.md
├─ 怪物/
│  ├─ 模组名 怪物数据.md
│  └─ 模组名 怪物描述.md
├─ 模组/
│  ├─ 原文/                 00-全文.md · 01-分段清单.md · segments.json
│  ├─ 正文.md               术语统一后的工作底稿
│  ├─ 术语表.md
│  ├─ 术语台账.json
│  └─ 加工进度.json
├─ 资料附件/                地图 · 立绘 · 备份 · 外部资料
├─ npc/
│  ├─ 模组名 NPC人设.md
│  ├─ 模组名 NPC数据.md
│  └─ 模组名 NPC任务与地点.md
└─ 模组总索引.md
```

五个文件夹的名字与层级不许改，不许新增顶层目录，不许按人物、形态、怪物、场景拆文件。没有章节划分时建一章，章名按原文内容起。

玩家事件清单、任务、线索、遭遇、分支与场景速查并入文字流程的 S 小节。主持 CG 和白板用同一个 S 编号定位，需要 Canvas 时可用 `scripts/canvas_link.py` 让每个白板节点（含展开卡）通过顶部大号双链直达文字流程对应 `#Sxxx` 标题并写入回链。

## 来源与事实状态

每项原文事实都要能定位到源文件和章节或页码。PDF 文件页码与印刷页码分开记录；附录、地图及图片也要在读取清单中标明实际读取范围。只读过的资料才能标为已读。

把原文明示、依据原文作出的推断、可选建议和外部核验分开标注。推断记录依据并保留不确定性；可选建议不冒充原文内容；外部资料注明链接、规则版本和核验日期。关键事实无法确认时建 Q 条目，不以猜测填空。

## 编号

| 前缀 | 指什么 | 例 |
| --- | --- | --- |
| S | 场景／事件节点 | S001 雾港码头 |
| L | 地点 | L001 灯塔 |
| N | NPC | N002 港务官哈维尔 |
| M | 怪物 | M001 礁石食尸鬼 |
| C | 线索 | C003 烧焦的账页 |
| Q | 待确认事项 | Q001 第三章缺页 |

- 编号一经分配不再改。删掉条目就空着，不复用。
- 标题必须写编号加实际名称。模板占位名（「角色名」「场景名」）会被脚本判错。
- 更名要同步：总索引、各资料标题、所有指向它的链接。

## 总索引

H1 写【模组名 · 模组总索引】。以下作为 H2 章节，名称照抄：

- **备团入口**：开团前看哪几份，按什么顺序看
- **规则与模组概况**：规则与版本、模组版本、译本、适用范围、总章数
- **章节及实体索引**：表格，列含「编号」「名称」「主条目」「来源」，覆盖 S、L、N、M、C；NPC 另加「已确认形态」
- **资料读取清单**：文件、用途、版本、页数、抽取方式、已读范围、需 OCR 页、重复或冲突、未读原因
- **待确认事项**：Q 编号、对象、来源、影响、阻塞与否、处理与恢复点
- **新增数值**：数值、出现位置、来源（原文页码／外部资料链接／规则书）
- **完成情况与修改记录**：已完成的章、本次生成／修改／删除的文件

原文核对范围内未见的新增规则数值，在「新增数值」登记出现位置与来源。

全文与相关附录都已读完后，若确实没有 NPC 或怪物，在索引明确写【原文无NPC】或【原文无怪物】。资料未读完时写未确认并登记 Q 编号，不能把未知当作没有。

## 加工进度

`模组/加工进度.json` 记三件事：

```json
{"stage": "写CG", "done_chapters": ["第01章", "第02章"], "pending": ["第03章"], "open_questions": ["Q003"]}
```

中断后从这里恢复，只重做 `pending` 里的章，以及受新增资料影响的实体。记录已核对的底稿行范围，分章验收时交给 `--source-lines`。

**逐文件明细放这里，不要放总索引。** 接管旧稿时会有几十个文件的迁移映射、URL 编码路径、读取状态——写进总索引会让它涨到上百 KB，打开就卡，导航也就废了。总索引里的【资料读取清单】只保留文件级的几行摘要。

**体积红线**：总索引超过 80KB 就该拆分，`check_campaign.py` 会给 `index-bloat` 提示。导航文件的合理体量是几 KB 到二十几 KB。

## 备份目录

两处，不分家、不混用：

| 目录 | 谁写 | 装什么 |
| --- | --- | --- |
| `模组/.backup/<时间戳>/` | `terms.py` 自动 | 替换前的受影响文件，供 `undo` 用 |
| `资料附件/备份/<日期 说明>/` | 人工或模型 | 接管旧稿、重绘地图这类整目录快照 |

`.backup` 是脚本的工作区，不要手工往里放东西，也不当交付物引用。人工快照放资料附件，名字带说明（`20261017_接管旧稿`），日后能认出是哪一次。

## 接管已整理过的目录

1. **先备份**：整目录快照进 `资料附件/备份/<日期 说明>/`，再动任何文件。
2. **先读后改**：逐个读现有产物，记下手工写过的内容——那些不能覆盖。
3. **补齐缺项**：缺 `模组/原文/` 就跑 `intake.py`；缺 `正文.md` 就从原文复制一份再套术语。
4. **修引用**：改名或合并后，扫一遍死链，别留指向旧名的链接。
5. **旧版原件**收进 `资料附件/`，不删。

迁移映射、URL 编码路径、逐文件读取状态记进 `模组/加工进度.json`。

原文优先于索引：共用事实变动时，先核原文，再改总索引，最后同步关联资料。角色数值只维护在数据文档，场景 DC、奖励与部署在 S 条目维护并同步章节使用处。
